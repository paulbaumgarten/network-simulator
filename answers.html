Lesson 1 — Answers

The IP model: LAN, subnet and the router as gateway

Q1What is the purpose of the network prefix, and how does the subnet mask 255.255.255.0 separate the network part of an address from the host part?
Suggested answer

The network prefix identifies the network that a device belongs to; all devices sharing the same prefix are on the same subnet and can communicate directly. The subnet mask marks which bits of the address are the network part and which are the host part. In 255.255.255.0 the first three octets are all-ones (network) and the last octet is all-zeros (host), so 192.168.1.x is the network and x identifies the individual host.

Q2Two PCs have addresses 192.168.1.100 and 192.168.1.150. Are they on the same subnet? Justify using the subnet mask.
Suggested answer

Yes. Applying the mask 255.255.255.0, the network portion of both addresses is 192.168.1, which is identical. Only the host portion (.100 versus .150) differs, so both belong to the same subnet and can communicate without going through the router.

Q3What is a default gateway, and why does a PC need to know its gateway's address to reach a device outside the LAN?
Suggested answer

The default gateway is the router that connects the LAN to other networks. When a PC needs to reach an address that is not on its own subnet, it cannot deliver the traffic directly, so it sends it to the gateway, which forwards it onward. Without the gateway's address the PC has nowhere to send off-subnet traffic and can only reach local devices.

Q4The router has both a LAN IP and a separate WAN IP. Explain the role of each.
Suggested answer

The LAN IP (e.g. 192.168.1.1) is the router's address on the internal network; it is the address local devices use as their gateway. The WAN IP (e.g. 203.0.113.1) is the router's address on the external/public side; it identifies the router to the wider internet. The router bridges the two, forwarding traffic between the private LAN and the public WAN.

Q5How many usable host addresses does a /24 network provide, and why is that not simply 256?
Suggested answer

A /24 has 8 host bits, giving 28 = 256 total addresses, but only 254 are usable for hosts. Two are reserved: the all-zeros host address is the network identifier and the all-ones host address is the broadcast address, so neither can be assigned to a device.

Lesson 2 — Answers

DHCP: obtaining IP addresses dynamically

Q1List the four pieces of configuration a client typically receives from DHCP in this simulator, and state what each is used for.
Suggested answer
  • IP address — the client's own unique address on the LAN.
  • Subnet mask — tells the client which addresses are local versus remote.
  • Default gateway — the router address to send off-subnet traffic to.
  • DNS server — the address to send name-resolution queries to.
Q2Why is an address described as a "lease" rather than a permanent assignment? Give one advantage of leasing.
Suggested answer

A lease is temporary and expires (or can be released), after which the address returns to the pool. This lets a limited pool serve many devices that come and go, so addresses are not wasted on devices that are no longer present. It also makes the network easier to manage, since configuration is handled centrally rather than by hand.

Q3The default pool runs from .100 to .199. What is the maximum number of devices that can hold a lease at once, and what happens when the pool is exhausted?
Suggested answer

The pool spans .100 to .199 inclusive, which is 100 addresses, so at most 100 devices can hold a lease simultaneously. When the pool is exhausted, further requests fail and the simulator reports that no address is available; a new device cannot obtain a lease until one is released.

Q4Why must a client be able to reach the DHCP server over the network before it can obtain an address?
Suggested answer

DHCP is itself a network exchange: the client must send a request to the server and receive a reply. If there is no physical path to the DHCP server (for example the device is unconnected), the request cannot reach it and no lease can be granted. The client has no IP yet, so this initial exchange relies on the underlying link rather than on IP routing.

Q5Give one reason an administrator might reserve part of the address range outside the DHCP pool for manual assignment.
Suggested answer

Servers, routers and printers usually need a fixed, predictable address so that DNS records, firewall rules and clients can rely on them. Keeping those addresses outside the DHCP pool prevents the server from ever handing them out to another device and avoids conflicts.

Lesson 3 — Answers

DNS: zones, A and CNAME records, and resolution

Q1Explain the difference between an A record and a CNAME record, and give an example use for each.
Suggested answer

An A record maps a name directly to an IPv4 address (e.g. www.myschool.local → 192.168.1.101); it is used to point a name at the server hosting it. A CNAME record maps a name to another name, creating an alias (e.g. portal.myschool.local → www.myschool.local); it is used when several names should follow the same target so that only the underlying A record needs updating.

Q2When you resolved portal.myschool.local, describe the sequence of steps the resolver took to reach a final IP address.
Suggested answer

The resolver looked up portal.myschool.local and found a CNAME pointing to www.myschool.local. It then followed that alias and looked up www.myschool.local, found its A record, and returned the associated IP address (e.g. 192.168.1.101). The chain was CNAME → A → IP address.

Q3Why might using a CNAME be more maintainable than creating several separate A records when one server hosts several named sites?
Suggested answer

With CNAMEs, all the names point to a single canonical name that has one A record. If the server's IP address changes, only that one A record needs updating and every alias follows automatically. With separate A records, each name would have to be changed individually, which is more work and more error-prone.

Q4What happens to name resolution across the whole network if the DNS server is switched off or unreachable? What could still work, and how?
Suggested answer

Name resolution fails: names such as www.myschool.local can no longer be translated to addresses, so any command or request that relies on a name will fail. Connections made directly by IP address still work, because they do not require DNS. This shows DNS is a convenience/availability dependency, not part of the raw routing.

Q5The resolver limits how many CNAMEs it will follow. Why is such a limit necessary?
Suggested answer

CNAME records can point to other CNAMEs, and a misconfiguration could create a loop (A → B → A) or an excessively long chain. A limit stops the resolver following the chain forever, preventing it from hanging and allowing it to report an error instead.

Lesson 4 — Answers

Web servers: hosting page content

Q1Describe the request/response cycle for a single web page, naming the request method and the meaning of a 200 OK status.
Suggested answer

The client sends an HTTP request, typically GET /, asking for a resource. The server processes it and sends back a response consisting of a status line, headers and the page body (HTML). A 200 OK status means the request succeeded and the requested content is included in the response.

Q2Which port does plain HTTP use, and which does HTTPS use? Why does it matter that these differ?
Suggested answer

HTTP uses port 80 and HTTPS uses port 443. Using distinct ports lets a server offer both, and lets clients, firewalls and administrators distinguish encrypted from unencrypted traffic — for example to block port 80 while allowing 443, or to know that traffic on 443 is protected by TLS.

Q3When the Web service was disabled, what response did the client get, and what does this tell you about how servers handle requests to closed ports?
Suggested answer

The client received a "connection refused" message. This shows that a request to a port where no service is listening is rejected rather than served: a port is only useful if a service is actually running behind it, so disabling the service effectively closes that port to clients.

Q4Why is it useful to reach a website by name rather than by IP address, both for users and for the site operator?
Suggested answer

Names are easier for users to remember and type than numeric addresses. For the operator, a name provides a stable identity even if the underlying IP address changes: only the DNS record needs updating, and users keep using the same name. Names also allow several sites to be organised under one domain.

Q5The simulator serves one page per server. In reality a web server hosts many resources. What role does the path (the part of a URL after the host name) play?
Suggested answer

The path identifies which specific resource on the server is being requested (for example /about or /images/logo.png). The host name selects the server; the path selects what to return from that server. This lets one server host many distinct pages and files.

Lesson 5 — Answers

The terminal: ping, nslookup, curl, ipconfig

Q1What information does ipconfig report, and why is it usually the first command to run when a PC cannot reach the network?
Suggested answer

ipconfig reports the PC's own IP address, subnet mask, default gateway and DNS server. It is run first because it confirms whether the PC has valid addressing at all: if it has no IP, or the wrong gateway or DNS, that alone explains the failure and points to a DHCP or configuration problem before anything else is investigated.

Q2ping can succeed while curl fails for the same host. Give a scenario and explain why.
Suggested answer

If the host is reachable but its web service is switched off (or the relevant port is blocked by a firewall), ping succeeds because the host responds to the reachability test, but curl fails because there is no web service listening or the request is dropped. Reachability and a working application service are two separate things.

Q3What is the difference between what nslookup tests and what curl tests?
Suggested answer

nslookup tests only name resolution: it asks the DNS server to translate a name into an IP address and reports the result. curl tests the full application request: it resolves the name (if needed), routes to the server, and retrieves the web page. nslookup exercises DNS; curl exercises DNS plus routing plus the web service.

Q4You ping a domain name and it fails, but pinging its IP address succeeds. What does this tell you?
Suggested answer

The host itself is reachable (the IP works), so the problem is with name resolution: DNS is not translating the name to the address. This could be because no record exists for the name, the record is wrong, or the DNS server is off or unreachable. The fault lies in DNS, not in connectivity to the host.

Q5Why is it valuable that these commands operate on the network you built, rather than returning fixed sample output?
Suggested answer

Because the output reflects the actual configuration, the commands become genuine diagnostic tools: a misconfiguration produces a real failure that you can investigate and fix. This lets you learn cause and effect and practise troubleshooting, which fixed sample output could not teach.

Lesson 6 — Answers

Firewalls and filtering traffic

Q1Explain the difference between a default-allow and a default-deny firewall, and state which is generally more secure and why.
Suggested answer

Default-allow permits any traffic that is not explicitly blocked; default-deny blocks any traffic that is not explicitly allowed. Default-deny is more secure because it fails safe: anything the administrator has not consciously permitted is refused, so newly exposed or forgotten services are blocked by default rather than being open until someone notices.

Q2Why does the order of rules matter? Give an example where a poorly ordered rule set fails to achieve its intent.
Suggested answer

Because the first matching rule wins, a broad rule placed above a specific one can override it. For example, an ALLOW any : any rule placed above BLOCK any : 80 means the allow matches first and port 80 is never blocked. The specific block should come before the broad allow to take effect.

Q3You blocked port 80 but a PC can still reach the site over port 443. Explain why blocking one port does not block a service entirely.
Suggested answer

The web service listens on two ports: 80 for HTTP and 443 for HTTPS. A rule blocking port 80 only stops the plaintext path; requests on port 443 are unaffected and still reach the service. To block the service completely, both ports would need to be blocked.

Q4A firewall that is enabled but set to default-allow with no block rules provides little protection. Explain why.
Suggested answer

With no block rules and a default action of allow, every packet matches the default and is permitted. The firewall is switched on but is not actually filtering anything, so it offers no more protection than having no firewall at all.

Q5Give one advantage and one limitation of filtering traffic purely by IP address and port number.
Suggested answer

Advantage: it is simple and fast, and effectively controls which services can be reached from where. Limitation: it cannot inspect the content of the traffic, so it cannot detect attacks carried inside otherwise-allowed traffic (for example a SQL injection sent over an allowed port 443). It controls access to services but not what is done through them.

Lesson 7 — Answers

TLS certificates and Let's Encrypt

Q1What three checks does a client perform on a certificate during an HTTPS connection, and what does each protect against?
Suggested answer
  • Presence / trust: a certificate exists and is signed by a trusted CA — protects against a server with no verifiable identity.
  • Expiry: the current date is within the validity period — protects against reliance on old, potentially compromised credentials.
  • Domain match: the certificate is issued for the site being visited — protects against a valid certificate for one site being reused to impersonate another.
Q2What is the role of a Certificate Authority, and why must the client already trust the CA for the certificate to be meaningful?
Suggested answer

A Certificate Authority verifies an applicant's control of a domain and signs their certificate, vouching for the binding between the name and the identity. The client relies on a pre-installed list of trusted CAs; if it did not already trust the signer, anyone could sign their own certificate and the signature would prove nothing. Trust in the CA is what makes the certificate believable.

Q3Explain what "domain match" means and why a certificate for one domain should not be accepted for another.
Suggested answer

Domain match means the domain named in the certificate is the same as the site the client is connecting to. If a certificate for a.example were accepted on b.example, an attacker holding a legitimate certificate for their own domain could present it while impersonating a different site, defeating the purpose of verifying identity.

Q4Why do certificates have an expiry date rather than lasting forever? Give a security reason.
Suggested answer

Expiry limits the useful lifetime of a certificate and its associated key. If a key is compromised, the damage is bounded because the certificate will stop being trusted at expiry. Regular renewal also ensures records and ownership are re-verified periodically, keeping the trust information current.

Q5What does the Force HTTPS setting achieve, and why might a site operator enable it?
Suggested answer

Force HTTPS makes the server refuse plain HTTP so that all connections must be encrypted. An operator enables it to guarantee that users never accidentally send data over an unencrypted connection, closing the window in which credentials or content could be intercepted.

Lesson 8 — Answers

Denial of service (DDoS) and rate limiting

Q1Distinguish between a DoS and a DDoS attack. Why is the distributed form harder to defend against?
Suggested answer

A DoS attack comes from a single source; a DDoS attack comes from many sources at once. The distributed form is harder to defend against because the traffic is spread across many addresses, so simply blocking one source does not stop it, and the combined volume can be far larger. It is also harder to tell attack traffic apart from legitimate users.

Q2What is a bottleneck in the context of this attack, and where are the bottlenecks in your simulated network?
Suggested answer

A bottleneck is the point of limited capacity that the attack saturates first. In the simulated network the bottlenecks are the target server itself and the single link (uplink) leading to it through the router; once either is overwhelmed, legitimate requests cannot get through.

Q3Explain why a firewall alone is insufficient against a large volumetric attack.
Suggested answer

A firewall can drop unwanted packets, but it still sits on the single path to the server and must receive the traffic in order to filter it. A large enough flood can saturate the link or the firewall itself before filtering helps. Because everything funnels through one point, the firewall does not remove the underlying capacity bottleneck.

Q4Explain how rate limiting reduces the effect of a flood, and give one drawback of setting the limit too low.
Suggested answer

Rate limiting caps how many requests a source may send in a time period, so a single source cannot consume all the capacity and the server stays responsive to others. If the limit is set too low, legitimate users making normal numbers of requests may be throttled or blocked, harming the service for real users.

Q5Why does adding redundant capacity or an upstream scrubbing service help, when simply making one server larger may not?
Suggested answer

A single larger server is still one point that can be overwhelmed and one link that can be saturated. Redundant capacity spreads load across multiple servers and paths so there is no single point of failure, and an upstream scrubbing service or CDN absorbs and filters the flood before it reaches your link, removing the bottleneck rather than just enlarging it.

Lesson 9 — Answers

Man-in-the-middle interception

Q1What is a man-in-the-middle attacker, and what position on the network do they need to occupy?
Suggested answer

A man-in-the-middle attacker sits on the communication path between a client and a server, where traffic passes through or by them. From that position they can observe, and potentially alter, the data in transit. They need to be somewhere on the route, such as a shared network segment, a compromised device along the path, or an untrusted access point.

Q2Using your observations, contrast what the interceptor could read for HTTP versus HTTPS traffic.
Suggested answer

For HTTP the packets were plaintext and the interceptor could read the actual content (for example the request and page data). For HTTPS the packets were encrypted and the interceptor saw only unreadable data (••••••••), so the content was protected even though the packets still passed through them.

Q3Encryption protects the content of traffic, but an interceptor may still observe some information. Suggest what an attacker might still learn.
Suggested answer

Even with encryption, an attacker can typically see metadata: the source and destination IP addresses, the port (and therefore that it is HTTPS), the timing and size of the traffic, and often the domain being contacted. They cannot read the actual content, but they can learn who is talking to whom and roughly how much.

Q4Why is it dangerous to enter a password on a site served over plain HTTP, particularly on a shared or public network?
Suggested answer

Over plain HTTP the password travels in readable form, so anyone able to intercept the traffic can capture it. On a shared or public network many others may be positioned to eavesdrop, making interception far more likely. The credential could then be reused to access the account.

Q5Explain how HTTPS defends against a man-in-the-middle, referring to both encryption and the certificate check.
Suggested answer

Encryption ensures that even if the attacker sees the traffic, they cannot read or usefully modify it. The certificate check ensures the client is actually talking to the genuine server and not to the attacker impersonating it, because the attacker cannot present a valid, trusted, domain-matching certificate. Together they protect both the confidentiality of the data and the identity of the server.

Lesson 10 — Answers

Unsecured protocols (ports 80, 21, 25)

Q1For each of ports 80, 21 and 25, name the protocol and state what kind of data it carries.
Suggested answer
  • Port 80 — HTTP: web page requests and content, in plaintext.
  • Port 21 — FTP: file transfers, historically including login credentials in the clear.
  • Port 25 — SMTP: email messages transferred between mail servers, unencrypted in the basic protocol.
Q2What does "attack surface" mean, and how does leaving unencrypted services open increase it?
Suggested answer

The attack surface is the total set of points where an attacker could try to interact with or exploit a system. Each open service and port is one such point. Leaving unencrypted services open adds points that are both reachable and inherently insecure (data can be read in transit), so it enlarges the attack surface and gives an attacker more opportunities.

Q3For one of the three protocols, name its secure alternative and explain what that alternative adds.
Suggested answer

Accept any correct pairing, for example: HTTP → HTTPS, which adds TLS encryption and server authentication; FTP → FTPS or SFTP, which encrypts both the credentials and the file data; SMTP → SMTP with STARTTLS, which encrypts the mail transfer. In each case the alternative adds encryption (and often identity verification) so the data can no longer be read in transit.

Q4Blocking a port at the firewall and switching to an encrypted protocol are two different responses. Explain the difference and when you might use each.
Suggested answer

Blocking a port stops the service from being reached at all from the blocked sources; you use it when the service is not needed there, or to reduce exposure. Switching to an encrypted protocol keeps the service available but protects its data in transit; you use it when the service is required but must be secured. They can be combined: encrypt what you keep, and block what you do not need.

Q5Why might an organisation still be running these legacy protocols, and what makes migrating away difficult?
Suggested answer

Older systems and equipment may only support the legacy protocols, and long-standing processes or third parties may depend on them. Migration can require replacing or reconfiguring software, coordinating with external partners, testing for compatibility and retraining staff, all of which take time and money and carry a risk of disruption — so insecure defaults often persist.

Lesson 11 — Answers

Application attacks: phishing, SQL injection, XSS

Q1Explain how phishing exploits a user's inability to verify a site's identity, and how HTTPS with a valid certificate helps.
Suggested answer

Phishing relies on a user believing a fraudulent site or message is genuine. Without HTTPS and a valid certificate there is no reliable identity indicator, so a convincing look-alike is hard to distinguish from the real site. HTTPS with a valid, domain-matching certificate lets the browser confirm the site's identity and show a secure indicator, giving the user a means to check they are on the genuine site (though it does not stop them being deceived in other ways).

Q2Describe how SQL injection works at a high level, and explain why parameterised queries prevent it.
Suggested answer

SQL injection happens when user input is concatenated directly into a database query, so crafted input is interpreted as part of the query's code and changes its meaning (for example bypassing a check or reading extra data). Parameterised (prepared) queries separate the query structure from the data: the input is supplied as a value that is never treated as code, so it cannot alter the query and the injection fails.

Q3Describe how cross-site scripting works, and explain what "escaping output" means and why it defends against XSS.
Suggested answer

XSS happens when a site includes untrusted input in a page without neutralising it, so an attacker's script runs in another user's browser. Escaping output means converting characters that have special meaning in HTML (such as < and >) into harmless equivalents so the input is displayed as text rather than executed as markup or script. This prevents the injected content from being treated as code.

Q4SQL injection and XSS both stem from mixing untrusted input with something else. Explain the common underlying cause and the general principle that prevents both.
Suggested answer

In both cases untrusted input is mixed with code or markup and then interpreted, so data is mistakenly treated as instructions (a query in SQLi, page/script in XSS). The general principle that prevents both is to keep data and code separate and never trust input: validate/sanitise input, and safely encode or parameterise it for the context in which it is used so it can only ever be treated as data.

Q5Why are application-layer attacks not stopped by a network firewall that filters on IP address and port alone?
Suggested answer

These attacks are carried inside legitimate-looking requests to services the firewall is meant to allow (for example a normal HTTPS request to port 443). A firewall filtering only on IP address and port permits that traffic and does not inspect its content, so the malicious payload passes through. Defending against them requires controls at the application itself, such as input validation, parameterised queries and output escaping.

Lesson 12 — Answers

Expired and missing certificates

Q1Distinguish between a missing, an expired and a self-signed certificate, and describe the client's response to each.
Suggested answer
  • Missing: no certificate is presented, so a secure connection cannot be established at all — the client refuses or reports HTTPS as unavailable.
  • Expired: a certificate exists but its validity period has passed, so the client no longer trusts it and warns/refuses.
  • Self-signed: the certificate is signed by the server itself, not a trusted CA, so the client cannot verify its authenticity and shows a warning.
Q2Why does a certificate that was valid yesterday stop being trusted once its expiry date passes?
Suggested answer

Trust is deliberately time-limited. The expiry date is part of what the CA signed, and clients enforce it so that credentials must be periodically re-verified and renewed. Beyond expiry there is no current assurance the key is still safe or the details still accurate, so the certificate is treated as untrusted regardless of past validity.

Q3A self-signed certificate still encrypts the connection. Explain why clients nonetheless warn about it, referring to the CA.
Suggested answer

Encryption alone does not prove who is at the other end. A self-signed certificate has not been verified and signed by a trusted Certificate Authority, so there is nothing to confirm the server's claimed identity — an attacker could equally self-sign a certificate while impersonating the site. The client warns because the connection may be private but the identity is unverified, leaving it open to a man-in-the-middle.

Q4Why is it a security problem when users become accustomed to clicking past certificate warnings?
Suggested answer

Certificate warnings are meant to signal genuine danger, such as an interception or an impersonated site. If users routinely dismiss them (for example because a site's own certificate is often misconfigured), they lose their value as a warning and users will also click past the warnings that indicate a real attack, defeating the protection.

Q5Automated issuance and renewal (as offered by Let's Encrypt) directly address one of these failures. Which one, and how?
Suggested answer

They address the expired-certificate failure. By issuing certificates automatically and renewing them before they expire without manual intervention, the process ensures a valid certificate is always in place, so sites are far less likely to be left serving an expired one.
